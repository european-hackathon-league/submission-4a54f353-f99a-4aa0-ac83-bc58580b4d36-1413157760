## 4. Plumbing

**`src/app/api/[...path]/route.ts`:**
- Lines 14-26 compile every endpoint path into a regex, turning each `:param` into `([^/]+)`.
- `match()` (lines 28-35) returns the first endpoint whose method and regex both match.
- No match returns 404 with `{error}` (line 40).
- Acting user (line 43): `x-user-id` header, then the `rs_user` cookie, then the default `"u-lena"`. A user not in the store gets a 401 (line 45).
- The query is parsed from the search params with the endpoint's Zod schema; the body is parsed from JSON, with an empty body treated as `{}` (lines 48-53).
- It then calls `handlers[name]({params, query, body, user})` from `src/mock/handlers.ts`.
- Outside production, the response is checked against the contract and only logged if it doesn't match (lines 58-61).
- Errors: a ZodError becomes 400 `{error: "Invalid request", issues}`; an `ApiError` becomes `{error}` with its own status; anything else is 500 `{error}` (lines 63-68).
- GET, POST, PUT, PATCH and DELETE are all exported (line 71).

**`src/lib/api/client.ts`:**
- Base URL is `process.env.NEXT_PUBLIC_API_BASE_URL ?? "/api"` (line 8).
- `buildPath` (lines 26-35): replaces `:params` (URL-encoded) and throws if one is missing. It drops query values that are undefined or `""` and stringifies the rest with URLSearchParams.
- `api()` (lines 37-50):
  - Always sends `content-type: application/json`, plus `x-user-id` when the cookie is set.
  - Sends a body whenever the endpoint declares one; if the caller passes none, it sends `{}`.
  - On a non-2xx response it throws `ApiRequestError(status, json.error ?? "Request failed (N)", json.issues)`. The backend error shape the UI expects is therefore `{error: string, issues?}`.

**`src/lib/api/hooks.ts`:**
- `useApi` (lines 9-19) uses the query key `[name, params, query, body]`.
- `useApiMutation` (lines 25-37) calls `qc.invalidateQueries()` with no filter on success, so every query refetches. It shows a success toast if configured, and on error shows `toast.error(e.message)` unless `silent` is set.
- Query defaults (`src/components/providers.tsx:12`): staleTime 15s, no refetch on window focus, retry 1.

**`src/lib/session.ts`:**
- The cookie is `rs_user` (line 5).
- `getUserId` reads `document.cookie` and returns null during SSR (lines 7-11).
- `setUserId` writes the cookie with path `/`, a 30-day max-age and samesite=lax, or clears it when given null (lines 13-16).
- `src/components/shell/app-shell.tsx:24-36`: redirects to `/login` when there is no cookie and only enables the shell queries once the user is set.
- Persona switching and login call `setUserId` and then `qc.clear()` (`persona-menu.tsx:26`, `login-view.tsx:33`).
- There is no middleware or proxy file.

  - Otherwise: needs `Authorization: Bearer &lt;token&gt;`.
  - Tokens are verified with HS256 and `SUPABASE_JWT_SECRET`, or with JWKS (RS256/ES256), audience `authenticated`. The `sub` claim is the user id (`:47-62`).
  - The user must exist in `app_user`: a non-uuid id gives 401, an unknown user gives 403 (`:65-74`).
  - The actor string is `"{role}:{id}"`.
- **Mode selection**: `auth_mode` defaults to `"auto"`, which becomes `supabase` if `SUPABASE_URL` is set, else `dev` (`config.py:31,80-81`).
- **CORS**: `CORS_ORIGINS`, default exactly `http://localhost:3000,http://localhost:5173` (`config.py:34`). `.env` and `.env.example` hold the same value. Credentials are allowed, methods and headers are `*`, and `x-request-id` is exposed (`main.py:19-23`).
- **Request id**: the `x-request-id` header is echoed back, or generated if missing (`deps.py:31-40`).
- **Error format**: `{"detail": "&lt;string&gt;"}` for `HTTPException` and the mapped exceptions (`deps.py:42-51`):
  - `NotFound` → 404
  - `StaleVersion`, `InvalidTransition`, `InvalidAction` → 409
  - any other `ValueError` → 422
  - Pydantic validation errors use FastAPI's default `{"detail": [{loc, msg, type, …}]}`.
  - Unmapped DB errors return a 500.
- **Transactions**: one per request, so audit rows commit together with the change (`deps.py:23-27`).
