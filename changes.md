# Changes Log: Decisions Made During Implementation

Every change against `plan.md`, `CLAUDE.md`, `architecture.mmd` or the first database draft that was decided during implementation, with the reason and who decided. Newest phase last. Small implementation details that follow the plan are not listed here; they are in the commit bodies.

## Review fixes (Devin, phases 0 and 1)

Reviewer findings on commits `8d9d1e8` (phase 0) and `6dfc8e2` (phase 1). Migrations 0001 to 0007 are applied and checksum-protected, so the SQL fixes are in the new migration `0009_review_fixes.sql`.

| # | Change | Reason | Decided by |
|---|---|---|---|
| R0.1 | `source_record.content_hash` is no longer unique: the unique constraint is dropped, a plain btree index `source_record_content_hash` replaces it. Records are deduplicated by their source-native identity (`record_id`, PK); the hash is a duplicate-detection hint. | Distinct customers can write identical text (G70: 4,000 verbatim IDs, 3,993 distinct texts); a unique hash over text would drop real customers. The seed already put the verbatim ID into the hash, so seeding was not affected. | Reviewer (Devin), applied by Claude |
| R0.2 | Requirement rank is computed on read per weight profile: new view `requirement_rank` (latest case score of the profile × the profile's cost multiplier, for every profile of the matching config). `requirement.rank_score` is documented as a cache for the config's default profile only. | Case scores exist per weight profile (vehicle × market); one stored column would be overwritten by whichever profile was scored last. A view keeps it simple and needs no extra table. | Reviewer (Devin), applied by Claude |
| R0.3 | Weight check `weights_valid`: non-empty object, every weight a JSON number ≥ 0, sum > 0 (replaces `weights_non_negative`). Rejection tests for all-zero, empty, negative, `"NaN"`, numeric strings and null. | All-zero weights passed the old check but the scorer divides by the sum; the old text-to-numeric cast also accepted the string `"NaN"` (NaN ≥ 0 is true in Postgres). | Reviewer (Devin), applied by Claude |
| R0.4 | `README.md`: one requirement per confirmed case and BMW line, optionally split per market. | Matches the design (requirements are per line, change 0.3). | Reviewer (Devin), applied by Claude |
| R1.1 | Audited writes are atomic: `audit.insert`, `insert_many_returning` (the whole call), `update` and `tombstone` validate the actor, table, columns and key before any mutation and run mutation + audit event inside `audit.atomic(conn)` (own transaction on autocommit connections, savepoint inside a transaction; an idle non-autocommit connection keeps the commit with the caller). Tests: bad actor on autocommit, unknown key column, simulated audit failure, failing third batch, savepoint inside a caller transaction. | On an autocommit connection a failing audit insert left the row committed without its audit event, which breaks the audit-trail guarantee. | Reviewer (Devin), applied by Claude |
| R1.2 | Same as R0.1, enforced in SQL by migration 0009 (constraint found by catalog lookup, not by an assumed name). | Migration 0003 created `content_hash text not null unique`. | Reviewer (Devin), applied by Claude |
| R1.3 | `audit.update` compares real values (vectors element-wise via numpy, other values JSON-normalized) and redacts vectors only in the audit payload. Test replaces a feature embedding and checks that an identical vector is no change. | Comparing redacted values turned every non-null vector into `<vector>`, so replacing an embedding was silently skipped. | Reviewer (Devin), applied by Claude |
| R1.4 | `db.with_database(conninfo, dbname)` (psycopg `make_conninfo`) switches databases for URL, URL with query parameters (Unix socket) and keyword conninfo; the test fixtures use it. `migrate.apply_all` no longer looks for `127.0.0.1` in the URL: `localdb.ensure_supabase_roles` creates missing Supabase roles only when the current user may create roles (no-op on Supabase). Unit test with four conninfo forms. | `uri.rpartition("/")` breaks on socket and keyword conninfo; the URL check skipped role creation on a local socket server. | Reviewer (Devin), applied by Claude |
| R1.5 | Raw storage is write-once: `storage.put` accepts the same ref with identical bytes (idempotent re-runs) and raises `storage.RawRecordConflict` for different bytes. Local backend uses exclusive create; Supabase uploads with `upsert = false` and on failure downloads and compares. Tests for the local backend. | Raw evidence could be silently overwritten (local write replaced bytes, Supabase used upsert), which would break the traceability of stored quotes. Callers use dated or content-addressed refs. | Reviewer (Devin), applied by Claude |
| R1.6 | `next_case_id()` pads to four digits up to 9999, then uses the plain number (`CASE-10000`). Boundary test 9999 / 10000 / 10001. | `lpad(..., 4)` truncates, so case 10000 became `CASE-1000` and collided. | Reviewer (Devin), applied by Claude |
| R1.7 | `strict_schema` raises `UnsupportedSchema` for open objects (`dict`, `dict[str, X]`, models without fields) instead of turning them into always-empty objects. It also no longer strips fields named `title` or `default` (property maps are walked as maps, not as schema nodes). | Silent meaning change: the model could never return the dict content. The field-name stripping was found while fixing this. Output models must use lists of key/value items instead of open dicts. | Reviewer (Devin), applied by Claude; field-name fix: Claude |
| R1.8 | `audit.column_types` no longer caches an empty result for a table that does not exist yet. | Found while adding the column validation of R1.1: a lookup before a migration would have cached "no columns" for the whole process. | Claude |

## Phase 3: signal contract and validation gate

| # | Change | Reason | Decided by |
|---|---|---|---|
| 3.1 | The per-config source filter is applied when reading (case figures, boards), not in the gate. The gate only rejects unknown sources. | One signal serves several configs (vehicle x market); hiding it in the gate would hide it for every PM. | Claude |
| 3.2 | Embedding text: LLM summaries are embedded alone; label-based seed summaries (and heuristic ones) embed `feature_hint + quote` instead. | The label summary repeats the BMW kind label ("Likes: ..."), which would split likes and complaints about the same problem into different cases. | Claude |
| 3.3 | Quote matching tolerates differences in whitespace, curly quotes, dashes and letter case, but always stores the exact span of the original text (`quote`, `quote_start`). | LLMs normalize punctuation; the stored quote must still be an exact substring of the record. | Claude |
| 3.4 | Duplicate rule: same record + kind + quote + feature hint, or the same author posting the same text in another record of the same source (cross-post). | One verbatim can legitimately carry several signals about different features. | Claude |
| 3.5 | A competitor signal without a known `competitor_id` is quarantined and stored as `evidence_role = market` (original role in `extra.proposed_evidence_role`). | The database requires `competitor_id` for competitor evidence; this way it can never count as a competitor fact by accident. | Claude |
| 3.6 | Signals whose record was published before the line's `on_sale_since` are tagged `vehicle_role = predecessor` (kept valid, reason in `extra.role_reason`). | Older-generation evidence is kept and tagged (CLAUDE.md). | Claude |
| 3.7 | Out-of-scope wording (pricing, regulation, homologation) is tagged `scope_tag = out_of_scope`, kept valid but excluded from cases. | Scope is a tag the PM can see, not a deletion. | Claude |
| 3.8 | PM delete of a quarantined signal also purges the source record text when no other signal uses that record. | "Content purged, tombstone kept" (CLAUDE.md); the record would otherwise keep the purged content. | Claude |
| 3.9 | `audit.update_many` (single-column key, batched UPDATE ... FROM VALUES, one audit event per changed row, atomic) for pipeline updates such as embeddings and case assignment. | 13,105 embedding updates; one round trip per row is too slow on a remote database. | Claude |
| 3.10 | Car-area eval baseline: keyword heuristic 34.7 % on 300 verbatims; the LLM tagger eval (`python -m app.signals.eval_car_area`) runs once the OpenAI key is set. Agents tag car areas with the LLM, never with the heuristic. | The heuristic is only the offline fallback; its accuracy is too low for agent tagging. | Claude |
